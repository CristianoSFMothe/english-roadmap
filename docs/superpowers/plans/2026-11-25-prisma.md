# Prisma como ORM — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trocar todo o acesso ao banco de `pg` (SQL à mão) pelo Prisma 7, com o schema e a
migração inicial versionados, e recriar o banco do Supabase do zero a partir dela.

**Architecture:** `prisma/schema.prisma` descreve as 15 tabelas (4 do Better Auth, 8 do app
e 3 das Lições) com os mesmos nomes de tabela e coluna de hoje (`@@map`/`@map`). O Prisma
Client usa o driver adapter `@prisma/adapter-pg` e fica em `lib/db.ts`. As funções de
`lib/*.ts` mantêm assinatura e retorno, então as rotas não mudam. O que depende de
operadores `jsonb` ou de trava atômica continua em `prisma.$queryRaw`.

**Tech Stack:** Next.js 15, TypeScript 5.9, Prisma 7.10.1 (`prisma`, `@prisma/client`,
`@prisma/adapter-pg`), `pg` 8, Better Auth 1.x (`better-auth/adapters/prisma`), Supabase
Postgres 17.

**Spec:** `docs/superpowers/specs/2026-11-25-prisma-design.md` (as tabelas das Lições vêm de
`docs/superpowers/specs/2026-11-25-licoes-design.md`, seção "Banco").

## Global Constraints

- Prisma fixo em **7.10.1** nos três pacotes (a tag `latest` de `prisma` aponta para 8.0 RC).
- Nomes de tabela e coluna no banco **iguais aos de hoje**. Tabelas do Better Auth com colunas
  em camelCase (`userId`, `createdAt`); tabelas `app_*` em snake_case.
- `DATABASE_URL` = Transaction pooler (porta 6543), usado pelo app. `DIRECT_URL` = a mesma
  URL na porta 5432 (Session pooler), usado só pelo CLI do Prisma.
- TLS: segue o `sslmode` da URL. Sem `sslmode`, TLS com `rejectUnauthorized: false` para
  hosts que não são `localhost`/`127.0.0.1`; sem TLS para esses dois.
- Pool do adapter com `max: 3`, `idleTimeoutMillis: 10_000`, `connectionTimeoutMillis: 15_000`.
- Todo SQL que continua escrito à mão usa `prisma.$queryRaw` com template (parâmetros),
  nunca `$queryRawUnsafe` nem concatenação.
- As funções exportadas de `lib/server-data.ts`, `lib/lessons.ts` e `lib/pron-store.ts`
  mantêm nome, parâmetros e formato de retorno de hoje.
- Datas `date` (`lesson_date`, `start_date`) entram como `new Date("YYYY-MM-DDT00:00:00Z")`
  e saem com `toISOString().slice(0, 10)`. Nada de `getFullYear()`/`getDate()` em datas
  vindas do Prisma.
- RLS ligado em todas as tabelas, sem políticas.
- O banco só é apagado depois de o usuário confirmar **na hora** (Task 5).
- Comentários e mensagens em português do Brasil, como no resto do código.
- Commits com o rodapé `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Data da lição trocando de dia.** O `pg` devolve `date` como meia-noite local, e o Prisma
   devolve como meia-noite UTC. Em São Paulo (UTC-3), ler a data com getters locais mostra o
   dia anterior. A lição de `2026-11-25` tem que voltar como `"2026-11-25"`. Teste: smoke da
   Task 5, `createLesson`/`getLesson`.
2. **Dois cliques em "Gerar 3 respostas".** A segunda chamada de `setImprovements` para a
   mesma questão tem que devolver `null` e não sobrescrever. Teste: smoke da Task 5.
3. **Login com o adaptador novo.** Um campo do Better Auth com nome diferente no schema só
   quebra no primeiro login. Criar usuário, conta e sessão pelo adaptador tem que funcionar e
   cair nas colunas certas. Teste: smoke da Task 5, via `auth.$context`.
4. **Build sem banco.** Importar `lib/db.ts` sem `DATABASE_URL` não pode lançar erro (o build
   da Vercel importa as rotas). `databaseConfigured` fica `false` e a pronúncia vira no-op.
   Teste: Task 2, passo 5.
5. **Erro de conexão legível.** Com senha errada, banco inexistente ou host que não resolve,
   o `/api/health` tem que continuar dizendo o motivo em uma frase, mesmo com o erro agora
   embrulhado pelo Prisma. Teste: Task 2, `describeDbError` com `cause` aninhado.

- [ ] **Step 2: Implementar `lib/db-config.ts`**

exatamente as mensagens de `databaseStatus()` de hoje (`28P01`, `3D000`, `ENOTFOUND`,
timeout, certificado, genérico com `slice(0, 120)`).

await ctx.adapter.create({ model: "account", data: { id: `${id}-acc`, accountId: "g-1", providerId: "google", userId: id, scope: "calendar.events", createdAt: new Date(), updatedAt: new Date() } });
const sessao = await ctx.internalAdapter.createSession(id);
check("sessão criada pelo Better Auth", () => { if (!sessao?.token) throw new Error("sem token"); });
await checkAsync("googleGrant lê a conta", async () => { const g = await googleGrant(id); if (!g.connected || !g.calendar || g.offline) throw new Error(JSON.stringify(g)); });

// Dados do usuário
await saveProfile(id, sampleProfile);

await savePlan(id, { id: `${id}-p2`, createdAt: Date.now(), profile: sampleProfile, weeks: [] });

const dados = await loadUserData(id);
// plano ativo é o p2, progresso com currentWeek 3, perfil igual ao salvo

// Lições (Review Focus 1 e 2)
const l = await createLesson({ userId: id, date: "2026-11-25", level: "A1", weekN: 1, questions: [q1], study: estudo });
check("data da lição volta igual", () => { if (l.date !== "2026-11-25") throw new Error(l.date); });
// assuntosRecentes(id) === [estudo.topic]
await saveAnswer({ userId: id, lessonId: l.id, questionId: "q1", answer: "I is", result: errado, totalQuestoes: 1 });
// getLesson(id, "2026-11-25") com completedAt preenchido e results.q1.correct === false
// errosRecentes(id) com 1 item; historico(id) com { date: "2026-11-25", answered: 1, correct: 0 }; pendentes(id) vazio
const primeira = await setImprovements({ userId: id, lessonId: l.id, questionId: "q1", improvements: [m1] });
const segunda = await setImprovements({ userId: id, lessonId: l.id, questionId: "q1", improvements: [m2] });

// Vocabulário, pronúncia e agenda

await saveStoredPron({ [`smoke ${id}`]: "smôuk" });
await saveStoredPron({ [`smoke ${id}`]: "outra" });   // não sobrescreve
// getStoredPron([`smoke ${id}`]) === { [`smoke ${id}`]: "smôuk" }
await recordCalendarExport({ userId: id, planId: `${id}-p2`, calendarId: "c", calendarName: "n", eventCount: 2, startDate: "2026-11-30" });
// prisma.calendarExport.findFirst({ where: { userId: id } }).startDate.toISOString().slice(0,10) === "2026-11-30"

// Limpeza: apagar o usuário apaga tudo dele (cascade)
await prisma.user.delete({ where: { id } });
await prisma.pron.deleteMany({ where: { text: `smoke ${id}` } });
// prisma.lesson.count({ where: { userId: id } }) === 0 e prisma.profile.count(...) === 0
